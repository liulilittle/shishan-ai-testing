# 屎山挑战赛风格 · AI 测试题库

> English version: [README.en.md](./README.en.md) · 英文版见 [README.en.md](./README.en.md)

一个用于**测试 AI 能否改对真实业务场景 BUG** 的 AI 测试题库。每道题是一条真实业务链路上的"屎山"代码:按正常业务代码的样子写,但刻意埋入可复现的缺陷。AI 的任务是定位并修复这些 BUG;修复是否成功,由 **单元测试(期望表现)** 判定。

- 段位:钻石 DIAMOND(D-001~D-005)、王者 KING(K-001~K-005),共 10 题
- 前端:ASP.NET Core MVC 验证台,点"验证"运行该题单元测试
  - 全部通过 = 进球 ⚽
  - 部分通过 = 打在门框上
  - 全部失败 = 球偏出(尚未改对)

## 目录结构

```
F:\shishan\
├── Shishan.sln
├── src/
│   └── Shishan.Api/             # ASP.NET Core MVC 主项目(题库页 + 验证台 + 数据 API)
├── topics/                      # 题目工程(每题一个独立项目,含 BUG,正常代码风格)
│   ├── Shishan.Domain.D001/ ... # D001~D005, K001~K005
├── tests/                       # 判定测试(每题一个独立测试项目,描述期望表现)
│   ├── Shishan.Tests.D001/ ...
├── solutions/                   # 答案区(每题正确实现,与题目分开)
│   ├── Shishan.Solution.D001/ ...
└── docs/                        # 题目说明文档(中英双语,互相索引)
```

**答案与题目分离**:`topics/` 是给 AI 修的题目工程(含 BUG),`solutions/` 是每题的正确实现(参考答案),`tests/` 是判定基准。AI 只能改 `topics/`,跑测试判定改对与否。

## 快速开始

```bash
# 1. 构建解决方案
dotnet build Shishan.sln

# 2. 启动验证台
dotnet run --project src/Shishan.Api --urls http://localhost:5088

# 3. 打开 http://localhost:5088/ 查看题库,点"验证"运行测试
```

## 判定闭环(如何验证 AI 改对)

1. **初始状态**:`tests/` 的测试全部按"期望表现"编写,题目库(`topics/`)含 BUG → 测试有红。
2. **AI 修复**:只修改 `topics/Shishan.Domain.XXX/` 下的领域代码。
3. **判定**:`dotnet test tests/Shishan.Tests.XXX` 全部通过 = 改对;有失败 = 未改对。

每个测试项目当前引用的是 `topics/` 题目版;答案版在 `solutions/`,可切换引用验证"题目可改对"(每道题保证答案版全绿)。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
